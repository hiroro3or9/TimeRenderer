# 記録漏れ（未記録の帯）の検出と穴埋め

> 設計案。未実装。

## 解こうとしている問題

作業記録アプリで一番起きるのは「記録を付け忘れる」こと。
離席検知は「記録しすぎ」を防ぐ仕組みだが、その逆——**記録が無い時間**は今のところ
どこにも現れない。日ビューを見ても、空白が「何もしていなかった」のか
「記録し忘れた」のかが区別できない。

一日の終わりに思い出せる量には限りがあるので、**その場で気付けること**を優先する。

## 何を「記録漏れ」とみなすか

対象にするのは **勤務記録（`WorkDayLog`）がある日の、勤務時間内だけ**。

```
勤務:  09:12 ══════════════════════════════════ 18:30
記録:       [設計 10:00-12:00]   [実装 13:00-17:00]
離席:                                        （なし）

ギャップ:  09:12-10:00    12:00-13:00    17:00-18:30
```

出勤していない日、勤務時間の外は一切対象にしない。
記録を付けない日まで穴だらけに見えると、機能そのものが無視されるようになる。

### 覆い（ギャップにしないもの）

| 種類 | 扱い | 理由 |
|---|---|---|
| 実体の `ScheduleItem`（`IsAllDay` を除く） | 覆う | 記録そのもの |
| 記録中の進行アイテム | 覆う | 今まさに記録している |
| 仮想アイテム（未消化の定期予定） | **覆わない** | 予定であって実績ではない。むしろ「予定はあるが記録がない」を拾いたい |
| 除外した離席（`AwayPeriod`） | 覆わない | 下記のとおり、そもそもデータが残っていない |
| 終日アイテム | 覆わない | 時間帯を持たない |

短いギャップは無視する（既定 15 分未満）。
トイレや小休止まで指摘されると、警告が背景になってしまう。

### 除外した離席はギャップとして出す

`AwayPeriod` は永続化していない。記録停止時に「除く」を選ぶと記録が分割され、
離席だった区間は単なる空白として残る。つまり、自分で空けた直後の時間が
ギャップとして出てくる。

**v1 はこれを許容する。** 帯が出たら「休憩として埋める」で1クリックで消せるうえ、
結果として残るのは「11:00-12:30 休憩」という、空白より情報量の多い記録になる。

離席区間を専用ファイルへ保存して黙らせる案もあるが、見えないデータで挙動が変わるだけで
空白は空白のまま残る。割に合わない。
指摘が煩わしいと分かった時点で、**離席の除外時に「離席」アイテムを自動で1件作る**方向へ
進める（ギャップ検出側は実体アイテムに覆われるので何も変えなくていい）。

## データ構造

保存はしない。**毎回算出する。**
状態として持つと、アイテムを編集したときにズレて信用を失う。

```csharp
// Models/UnrecordedGap.cs
public sealed record UnrecordedGap(DateTime Start, DateTime End)
{
    public TimeSpan Duration => End - Start;
    public DateTime StartTime => Start;   // 既存コンバーターに合わせた別名
    public DateTime EndTime => End;
    public double DurationHours => (End - Start).TotalHours;
    public string RangeText => $"{Start:H:mm}-{End:H:mm}";
    public string DurationText { get; }   // "45分" / "1時間20分"
}
```

`StartTime` / `EndTime` / `DurationHours` という名前を `ScheduleSegment` に揃えておくと、
`TimeToPositionConverter` / `DurationToHeightConverter` / `DateToPagePositionConverter` を
そのまま使い回せる。日をまたぐ勤務（深夜作業）では、セグメントと同じく**日単位に分割**して
から描画へ渡す。

## 算出（`Helpers/UnrecordedGapHelper.cs`）

ViewModel から切り離した純関数にする。判定が地味に間違えやすい部分なので、
入力と出力だけで確かめられる形にしておきたい。

```csharp
public static IReadOnlyList<UnrecordedGap> Detect(
    DateTime workStart,
    DateTime workEnd,
    IEnumerable<(DateTime Start, DateTime End)> covered,
    TimeSpan minDuration);
```

1. `covered` を開始時刻でソートし、重なりをマージする
2. `[workStart, workEnd]` からマージ結果を引く
3. `minDuration` 未満を捨てる

`O(n log n)`。当日の `workEnd` は `EndTime ?? DateTime.Now` で切る
（まだ終わっていない勤務の「これから」をギャップにしない）。

### 再計算のタイミング

`RebuildWorkDayMarkers()` と同じ場所（`UpdateVisibleDays()` の末尾）に
`RebuildUnrecordedGaps()` を足す。対象は `GetLayoutRange()` の範囲だけ。

当日ぶんは時間の経過で伸びるが、毎 tick 回すのは無駄なので

- 表示日・表示モードの変更時
- アイテムの追加・編集・削除時（`RecalculateLayout` 経由）
- 記録の開始／停止時
- 5 分ごとのタイマー tick

の4つで足りる。

## 見せ方（日／週ビューのみ）

予定バーの**背面**に薄い斜線の帯を敷き、中央に `未記録 45分` と小さな `＋`。
月・スプリント・タイムラインには出さない（情報密度が保たない）。

- 色は `Themes/Colors.xaml` と `DarkColors.xaml` に `UnrecordedGapBrush` を追加。
  **赤は使わない。** 責める見た目にすると、機能ごと切られる
- ホバーで少し濃くし、クリック可能だと分かるようにする
- 表示時間範囲（`DisplayStartHour` / `DisplayEndHour`）でクリップする
- 設定でオフにできる（既定オン）

統計ビューには `未記録 3時間20分` の1行を足す余地があるが、v1 では入れない。

## 穴埋めのフロー

ギャップをクリック → `GapFillDialog`。

```
┌ 未記録の時間を埋める ─────────────────┐
│ 12:00 - 13:00 （1時間）    [開始▼][終了▼] │
│                                            │
│ 候補                                       │
│  ・週次定例          （この時間の定期予定） │
│  ・実装（直前の続き）                       │
│  ・打ち合わせ        （よく使うタイトル）   │
│                                            │
│ タイトル [____________]  カテゴリ [▼]       │
│ メモ     [____________]                     │
│                                            │
│  [記録する] [直前を延長] [休憩として埋める] │
└────────────────────────────────────────────┘
```

候補の優先順:

1. `GetAppUsageStats(start, end)` の上位アプリ（後述の収集範囲の変更で実データが入る）
2. その時間帯に重なる定期予定のタイトル（仮想アイテムがそのまま根拠になる）
3. 直前・直後のアイテムのタイトル（「直前の続き」は延長ボタンでも出す）
4. `GetTitleSuggestions()` の定型タイトル

「休憩として埋める」は、無視リストのような新しい状態を持たずに済ませるための逃げ道。
普通のアイテムとして「休憩」を1件作るだけなので、統計にもそのまま乗るし、
気が変わったら消せる。**v1 では「このギャップを無視する」機能は作らない。**

穴埋めは通常のアイテム追加なので、取り消しは既存の `UndoManager` にそのまま乗る。

## アプリ使用の収集範囲を「勤務中ずっと」に変える

`ActiveWindowTracker` はいま **記録中しか収集しない**。
未記録の帯にはデータが無く、この機能の肝である「この1時間、実際は何をしていたか」を
出せない。ここを**出勤から退勤までの収集**に変える。

記録漏れは「記録していない時間」に起きるのだから、
「記録している時間だけ裏付けを取る」という現状は噛み合っていない。

### 収集する条件

```
収集する ＝ （勤務中 または 記録中） かつ 離席していない
```

- **勤務中**: 未退勤の `WorkDayLog` がある状態。出勤で開始し、退勤で停止する
- **記録中も残す**: 勤務記録を付けずに記録だけ使う場合を落とさないための OR
- **アプリ起動時**: 未退勤の勤務が残っていれば、そのまま収集を開始する

### 離席中は必ず止める

これは新しく要る処理。`ActiveWindowTracker` は5秒ごとに前面ウィンドウを見るだけなので、
席を外している間も**最後に見ていたアプリの区間が伸び続ける**。
記録中だけならまだ実害は小さかったが、勤務中ずっとに広げると
昼休みが「Chrome 1時間」として残り、そのまま穴埋め候補に出てしまう。**逆効果になる。**

`AwayDetector` の離席検知と連動させ、離席の開始で進行中の区間を閉じ、復帰で再開する。
離席の判定はスリープ・ロックも拾うので、閉じ忘れは起きにくい。

### 保存の量とタイミング

`SaveAppUsage` は毎回**全件を書き直す**。収集時間が2〜3倍に増えるとファイルも比例して育つ
（1日 300 区間・1区間 250 バイトとして 75 KB/日、60 日保持で 4.5 MB 前後）。

- 保持日数を **60 → 30 日**に短縮する。穴埋めの裏付けは直近しか使わない
- 書き出しは退勤時に加えて **10 分ごと**にも行う。落ちたときの取りこぼしを抑える
- それでも重いようなら、月別ファイルへの分割を検討する（v1 ではやらない）

### プライバシー

記録していない時間のウィンドウタイトルも残ることになる。歯止めを明示しておく。

- **退勤したら止まる。** 勤務時間外は収集しない。ここが「常時収集」との決定的な違い
- 収集そのものを設定でオフにできる（既存の `IsAppUsageTrackingEnabled`）
- ローカル（`%APPDATA%`）にのみ保存し、保持期間を過ぎたら自動で消える

収集範囲は `AppUsageScope`（0: 記録中のみ / 1: 勤務中ずっと）で切り替えられるようにし、
既定は 1 とする。0 に戻せば従来どおりの挙動になる。

なお `docs/away-detection.md` に「収集するのは記録中だけ」と書いてあるので、
この変更に合わせて追記が要る。

## 一括レビュー（v1.5）

退勤を登録したときに「未記録が2件（合計1時間20分）あります。確認しますか？」と促し、
`AwayReviewDialog` に近い一覧から順に埋める。
思い出せるうちに片付けられるので、実効性はこちらのほうが高い。
ただし v1 の表示・穴埋めが動いてからにする。

## 設定項目

`AppSettings` / `BuildSettings` / `ApplySettings` の3箇所をセットで更新する。

| キー | 既定 | 内容 |
|---|---|---|
| `ShowUnrecordedGaps` | `true` | 未記録の帯を日/週ビューに表示するか |
| `UnrecordedGapMinMinutes` | `15` | この長さ未満は無視（選択肢 5/10/15/30） |
| `AppUsageScope` | `1` | アプリ使用の収集範囲（0: 記録中のみ / 1: 勤務中ずっと） |
| `AskUnrecordedGapsOnWorkEnd` | — | v1.5。退勤時にまとめて確認するか |

## 実装の順序

コミットもこの単位で切れる。

1. `Models/UnrecordedGap.cs` / `Helpers/UnrecordedGapHelper.cs`（純ロジック）
2. `ViewModels/MainViewModel.Gaps.cs` — `UnrecordedGaps` と再計算のフック
3. `Views/DayWeekView.xaml` + テーマにブラシ追加（表示のみ・クリック無し）
4. `MainViewModel.AppUsage.cs` / `MainViewModel.WorkDay.cs` / `MainViewModel.Away.cs`
   — 収集範囲を勤務中へ拡大、離席との連動、保持日数と書き出し間隔
5. `Views/Dialogs/GapFillDialog.xaml(.cs)` + `IDialogService` / `DefaultDialogService`
6. `Views/SettingsPanel.xaml` + 設定3箇所、`docs/away-detection.md` の追記

3 まで入れれば「気付ける」ようにはなる。
4 は独立して価値がある（既存の「使用アプリ」表示の中身が濃くなる）ので、
5 の穴埋めダイアログより先に入れて挙動を確かめたほうがいい。
