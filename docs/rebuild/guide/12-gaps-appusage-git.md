# 12. 記録漏れ・使用アプリ・Git コミット

離席検知が「記録しすぎ」を防ぐ仕組みなのに対して、ここは逆に「**記録が無い時間**」を見つけて埋めるための仕組みです。

## 未記録の帯

出勤している日の勤務時間のうち、実績で覆われていない区間を破線の帯として日/週ビューに敷きます。日ビューの空白が「何もしていなかった」のか「付け忘れた」のかを、その場で区別できるようにするためです。

方針は3つ。

- **出勤している日だけ**。出勤していない日は一切指摘しません
- **保存しない**。表示のたびに勤務記録と実績から計算します。状態として持つと、アイテムを編集するたびに実態とずれます
- **15分未満は無視する**。トイレや小休止まで指摘すると、帯そのものが背景になってしまいます

未退勤の勤務は「今まで」で切ります。これからの時間を記録漏れにはしません。記録中の区間は覆いに含めます（まだアイテムになっていないだけなので）。定期予定の仮想アイテムは**含めません**。予定であって実績ではないうえ、「予定はあるのに記録が無い」こそ拾いたい対象です。

帯は右クリックで3つの埋め方を出します。自由入力（通常の編集ダイアログを帯の時間幅で開く）、使用アプリやコミットから埋める、ToDo から埋める。

## 使用アプリの記録

記録を止めた後に「この2時間、実際は何をしていたのか」を思い出せないことがあります。前面にあったアプリを自動で控えておき、その裏付けにします。

収集するのは**勤務中**（出勤〜退勤）です。当初は記録中だけにしていましたが、それでは記録漏れの時間帯に材料が何も残らず、穴埋めの助けになりませんでした。

ただし**ウィンドウタイトルを残すのは記録中だけ**にします。タイトルにはファイル名・URL・チャット相手が出るので、記録していない時間の中身まで残すのは踏み込みすぎです。タイトルを残す/残さないが切り替わった瞬間に、進行中の区間を区切ります。

取り方は、前面ウィンドウの切り替えイベントを拾うのが主、5秒のポーリングが保険です。ポーリングだけだと、数秒だけ触ったアプリが丸ごと消えます。同じアプリへすぐ戻ってきたときは区間を繋ぎ直し（Alt+Tab の途中経過で細切れにしない）、スリープなどで長時間空いたときは末尾を伸ばしすぎないよう上限を設けます。

アプリ名は実行ファイルの説明（FileDescription）から取り、プロセス Id と生成時刻の組でキャッシュします。UWP アプリは枠だけを持つホストプロセスが前面に見えるので、**子ウィンドウから本体のプロセスを探し直します**。これをしないと、ストアアプリが全部同じ名前で記録されます。

集めた区間は5分ごとにファイルへ書き出します（途中で落ちた日のぶんを失わないため）。保存先はローカルだけで、一定期間を過ぎたものは自動で消します。

予定を右クリックすると、その時間帯の内訳（アプリごとの時間と割合、記録中に見えていたタイトル別の時間）を表示できます。割合の分母は「範囲の長さ」ではなく「収集できていた合計時間」にします。

## Git のコミット履歴

アプリ名は「どこで作業していたか」しか語りません。コミットメッセージは「何をしていたか」を語ります。開発の時間帯では、こちらのほうが手がかりとして強いので、登録したローカルリポジトリから読みます。

制約を4つ置きます。

- **読むだけ**。`git log` と `git config --get` しか実行しません。作業ツリーにも索引にも触れないので、手元の git 操作と衝突しません
- **自分のコミットだけ**（`user.email` で絞る）。全ブランチを見るので、絞らないと他人のコミットが混ざります。マージコミットは除きます
- **保存しない**。必要になったときに読み直します。写しを持つと、リベースで消えたコミットがこのアプリの中にだけ残ります
- **止まらない**。git が無い・パスが消えた・応答しない、のいずれでも空を返して黙ります

git の起動は数百ミリ秒かかるので、**ユーザーが操作した直後にしか読みません**（帯の穴埋めと退勤時のふりかえり）。1リポジトリあたりと全体の両方に時間の上限を設け、超えたら諦めます。

リポジトリごとにプロジェクトコードを紐づけておけます。穴埋めのときに、そのリポジトリのコミットだけで構成される時間帯なら、コードまで自動で選ばれます。複数のリポジトリにまたがる時間帯では推測しません（どちらの案件か決められないのに片方を既定値にすると、そのまま確定されます）。

## 帯を埋めるダイアログ

上半分が証拠（その時間に使っていたアプリの内訳と、その時間に作ったコミット）、下半分が確定する内容（タイトル・カテゴリ・プロジェクトコード）です。離席の確認ダイアログと同じ形で、**証拠を見せてから聞きます**。勝手に記録を作らないのは、外していたときに嘘の記録が黙って残るのを避けるためです。

タイトルの候補は、**コミットが先**、その後ろに「過去に同じアプリを使っていた時間帯へ自分が実際に付けていたタイトル」が並びます。後者は使用アプリの履歴と実績の重なり時間を重みにして集めます（件数で数えると、5分の記録も3時間の記録も同じ1票になってしまいます）。

ただし**既定値**は学習結果を優先します。学習結果は帯全体を言い表しているのに対し、コミット1件は帯の一部でしかないからです。カテゴリも同じ材料から推測しますが、材料が薄いうち（重なりが30分未満）は推測しません。外した既定値を直す手間のほうが大きいためです。

作った実績の内容欄には、根拠（「使用アプリから復元: Visual Studio 42分 / Chrome 12分」「コミット: 14:12 …」）を残します。後から見て、実測なのか記憶なのかが分かるようにするためです。作成は取り消し履歴に積みます。
