# TimeRenderer 再構築キット

TimeRenderer（WPF / .NET 10 のタイムライン型作業記録アプリ）を、**ソースコードを持ち出せない別環境で1から作り直す**ための設計書と実装計画です。
生成AIに渡して少しずつ実装させることを前提に、**1回のセッションで読む量が少なくて済むよう**分割しています。

## 使い方（トークンが限られた環境向け）

1. **セッション開始時**に `AGENT_RULES.md` を渡す（約100行）
2. `plan/phases.md` から**今回のフェーズの節だけ**を渡す
3. フェーズ節の「読む設計書」に列挙された**ファイル（または節）だけ**を渡す
4. AIに実装させる → ビルド → テスト → 節末の「手動確認」を実施 → コミット
5. フェーズが1セッションに収まらない場合は、節内の「ステップ」ごとにセッションを分ける
   （ステップの区切りでビルドが通る状態になるように計画してある）

雛形は `plan/prompt-templates.md` を参照。

### 渡す量を減らすコツ

- 設計書は見出し（`##`）単位で独立して読めるように書いてある。必要な節だけ切り出して渡してよい
- 既に実装済みのクラスは「ファイル一覧とpublicメンバーの一覧だけ」を渡し、中身は渡さない
- 画面の見た目は `03-theme-and-styles.md` のトークンとスタイル名で指定してある。
  フェーズ1で共通スタイルを作っておけば、以降は「`BaseButtonStyle` を使う」などの指示だけで同じ見た目になる

## 完成形の規模（参考）

- 本体：C# 約2.8万行、XAML 約7千行（ファイル約190）
- テスト：TUnit で 239 件以上（純粋ロジック中心）
- 外部 NuGet パッケージ：本体は **0**（MVVM は自作）、テストは `TUnit` のみ

## このキットに含まれないもの

- **アプリアイコン**（`Assets/AppIcon.ico`、16/24/32/48/64/256px のマルチサイズ）。
  持ち出せない場合は `03-theme-and-styles.md` の「アプリアイコン」節の説明で作り直す
- 既存ユーザーデータの移行ツール（JSON の項目名は元アプリと同一にしてあるので、`%APPDATA%\TimeRenderer` をコピーすればそのまま読める）

## 表記ルール

- 「」で囲んだ日本語は **UI にそのまま表示する文字列**。句読点・全角/半角・空白まで同じにする
- `#RRGGBB` / `#AARRGGBB` は色。`{Token}` は `03` で定義する DynamicResource のキー
- 数値の単位は特記なければ px（WPF の DIP）
- 「（理由）」は実装判断の根拠。AIが勝手に「改善」して仕様を変えないための注記なので、削らずに渡す
