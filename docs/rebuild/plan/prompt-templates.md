# プロンプト雛形

`{…}` を埋めて使う。**毎回 AGENT_RULES.md を先頭に付ける**（短いので省略しない）。
設計書は「読む設計書」に挙げた節だけを切り出して貼る。見出し（`##`）ごとに独立して読めるように書いてある。

---

## 1. フェーズを始める

```
以下の規約・計画・設計書に従って、TimeRenderer のフェーズ{N}を実装してください。

# 規約
{AGENT_RULES.md の全文}

# 今回のフェーズ
{plan/phases.md の「P{N}」節}

# 設計書（該当節のみ）
{design/xx の該当節}

# 既存コードの概要
{8. の「公開メンバー一覧」で作ったもの。無ければ「フェーズ1なので既存コードなし」}

進め方：
- まずステップ1だけを実装し、作成・変更したファイルの全文を出力してください
- 設計書に書かれていないことは推測で足さず、質問してください
- 後のフェーズの機能は、節の「スタブ」に書かれた空実装だけ置いてください
```

## 2. 同じフェーズの次のステップへ進む

```
フェーズ{N}のステップ{K}に進んでください。
ステップ{K-1}までのビルドとテストは通っています。

# 変更があったファイルの公開メンバー（抜粋）
{8. で作ったもの}

# 設計書（ステップ{K}に関係する節のみ）
{…}
```

## 3. セッションが切れた後に再開する

```
{AGENT_RULES.md}

TimeRenderer の再構築を続けます。現在はフェーズ{N}のステップ{K}の途中です。

# 完了していること
- {実装済みの機能を箇条書き}

# 途中のファイル
{途中まで書いたファイルの全文。完成済みのファイルは公開メンバー一覧だけ}

# 残っている作業
{phases.md の該当ステップの残り}

# 設計書（残りの作業に関係する節のみ）
{…}
```

## 4. ビルドエラーを直す

```
次のビルドエラーを直してください。設計書の仕様は変えないでください。
警告も0件にしたいので、警告があれば併せて直してください。

# エラー・警告
{dotnet build の出力のうち error / warning の行だけ}

# 関係するファイル
{エラーが出たファイルの全文}
```

> WinForms との名前衝突（`Brush`, `Point`, `MessageBox`, `ContextMenu` …）が原因なら AGENT_RULES §6 のエイリアスで直す、と一言添えると早い。

## 5. テストが落ちたときに直す

```
次のテストが失敗しています。まず「テストが仕様どおりか」「実装が仕様どおりか」を
設計書の該当箇所と照らして判断し、間違っている側を直してください。

# 失敗したテスト
{テスト名・期待値・実際の値}

# テストコード
{…}

# 実装
{…}

# 設計書の該当箇所
{…}
```

## 6. 見た目の差を直す

```
画面の見た目が設計書と違います。スタイル・トークン・余白を設計書どおりに直してください。
新しい色やスタイルを勝手に作らないでください。

# 違う箇所
- {例：ToDo パネルの行の高さが大きい。期限チップの角が四角い}

# 設計書の該当箇所
{design/xx の XAML 仕様}

# 現在の XAML
{該当部分}
```

> 元アプリのスクリーンショットが持ち出せる場合は、同じ画面のスクリーンショットを並べて渡すと精度が上がる。

## 7. フェーズを締める（自己レビュー）

```
フェーズ{N}の実装が一通り終わりました。次の観点で自己レビューし、問題があれば修正してください。

1. phases.md の「作るファイル」がすべて揃っているか
2. 設計書の「」内の UI 文字列が一字一句同じか（全角/半角・句読点・空白）
3. 「壊してはいけないもの」（AGENT_RULES §4）に反していないか
   - 一括更新・読み込み中・Undo 適用中の抑止フラグ
   - Undo が元のインスタンスへ書き戻しているか
   - 設定を増やしたなら AppSettings と SettingsMapping の両方を更新したか
4. P/Invoke が LibraryImport と関数ポインタになっているか
5. スタブが後のフェーズの設計書どおりの名前・シグネチャか
6. ファイルが UTF-8(BOM付き)・CRLF か

最後に、このフェーズで作成・変更したファイルの一覧と、
次のフェーズへ渡す「公開メンバー一覧」（8. の形式）を出力してください。
```

## 8. 公開メンバー一覧を作らせる（次のセッションへ渡す量を減らす）

```
次のファイル群について、他のファイルから使われる部分だけを抜き出した一覧を作ってください。
メソッドの中身・private メンバー・コメントは不要です。

形式：
## ファイル名
- 型宣言（partial / record / enum など）
- public / internal のプロパティ（型・名前・get/set）
- public / internal のメソッド（シグネチャ）
- コマンド名
- XAML の場合は x:Name と、バインドしているプロパティ名の一覧

# 対象
{ファイルの全文}
```

## 9. 仕様の質問に答えるとき

AI から質問が来たら、まず設計書を検索して該当箇所を貼る。設計書に無い場合は、元アプリの挙動を人間が確認して一文で答え、
**同じ質問が次のセッションで出ないよう、設計書の該当節に追記しておく**。

```
質問への回答です。設計書 {design/xx §n} に次の記述があります：
{引用}
この仕様で実装を続けてください。
```

---

## 渡す量の目安

| 渡すもの | 目安 |
| --- | --- |
| AGENT_RULES.md | 約100行（毎回） |
| phases.md の1節 | 30〜60行 |
| 設計書の節 | 1フェーズで 200〜600行。多いときはステップ単位に分ける |
| 既存コード | 公開メンバー一覧のみ（中身は渡さない） |
